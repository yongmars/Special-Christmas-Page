# ノクトとルクスのクリスマス2026

黒猫のノクトと白猫のルクスのお部屋で、12月1日から25日まで毎日ひとつずつプレゼントを開ける特設ページです。Next.js App Router・React・TypeScriptで構成し、アカウントとデータベースは使用しません。

## 公開ページ

[特設ページを開く](https://yongmars.github.io/Special-Christmas-Page/)。PC・スマートフォンからログイン不要で利用できます。GitHub Pages版は端末の時計から日本時間を計算して、午前0時に扉を開きます。25日分の文章と素材をまとめて配信するため、ファイルを調べると未来の日の内容も閲覧できます。正式公開まで配布したくない素材は、追加する日まで手元で管理してください。

素材を更新して main にプッシュすると、GitHub Actions がテスト・静的ビルド・Pages公開を行います。手元での静的ビルドは `npm run build:pages` です。開発プレビューはローカルで起動してください。

## ローカルで開く

Node.js 24 と npm を使います。PowerShell でこのフォルダーを開き、初回は `npm.cmd ci`、続けて `npm.cmd run dev` を実行します。終了はそのターミナルで Ctrl+C です。

| 入口 | 用途 |
| --- | --- |
| [通常のお部屋](http://127.0.0.1:3016/) | サーバーの実際の日本時間で表示 |
| [12月1日のプレビュー](http://127.0.0.1:3016/dev/preview?date=2026-12-01) | 初日の壁紙を試す |
| [12月25日のプレビュー](http://127.0.0.1:3016/dev/preview?date=2026-12-25) | 25個の扉と3ゲームをすべて試す |

開発プレビュー上部の「設定」を開き、日付を変えて「日付を適用」を押してください。扉を選んで開封状態を切り替えたり、クリアを個別に設定したりできます。「プレビュー記録をリセット」は試遊用の記録だけを初期化します。通常画面と開発画面は保存先を分けています。ブラウザや接続先のホスト名が変わると記録も別になります。

## 立ち絵・物語・クイズの更新

お部屋と小話は同じ立ち絵設定を使います。現在はご提供のクリスマス衣装設定資料から正面ポーズを取り出した透過WebPを使用しています。新しい透過PNGやWebPは公開画像フォルダーに置き、`characters.json` の `image` を変更してください。ルクスは `lux`、ノクトは `noct` です。

日別素材は、対象日のJSONだけを編集します。たとえば12月3日の絵を替える場合は `assets/christmas/03/` に画像を置き、`content/days/03.json` の `image.file` にファイル名、`image.alt` に絵の説明を書きます。本文の改行はJSON文字列の中で `\n` と書けます。

| 種類 | 変更する項目 |
| --- | --- |
| 物語・イラスト・25日の特別コンテンツ | `title`、`image`、`body`、`lines`。セリフには話者 `who` と発言 `text` を登録 |
| 小話 | `title` と `lines`。会話順に並べると話者の立ち絵が付きます |
| クイズ | `question`、3つの `choices`、`answer`、`explanation`、`lines`。正解番号は **0＝最初、1＝中央、2＝最後**。9日分は `09.json` |
| 壁紙 | `images` に `file` と `alt` の組を追加。画像ごとにプレビューと保存ボタンが付きます。初日の仮壁紙は横長・縦長のPNG |
| ゲームの扉 | `gameId` でゲーム設定を参照。ゲームの公開日は `games.json` の `releaseDate` で一元管理 |

Next.jsサーバー版では未来の日の本文と画像をサーバー側で保管します。日別画像を `public/` に置くと直接配信されるため、公開を待つ絵は `assets/christmas/日番号2桁/` に置いてください。画像配信はその日付に登録されたファイル名だけを受け付けます。個人用の設定資料のコピーはGitの対象外です。

## ゲームを仕上げる

3作品はこの特設ページ内で動作します。神経衰弱は8組16枚、スライドは3×3と4×4、ジグソーは既存作品と同じ凹凸・90度回転・位置と角度による吸着を使う3×3です。ジグソーは矢印キーでマス移動、Enterまたはスペースで回転もできます。

1. 神経衰弱は `assets/christmas/06/` に画像を追加し、`games.json` の `faces[].file` と `backFile` を設定します。空欄なら記号を使います。スライドは `13/`、ジグソーは `20/` に画像を入れ、各ゲームの `image` を変更します。正方形の画像が適しています。
2. ゲーム本体は `components/games/` にあります。本体を入れ替えるときはゲーム詳細のコンポーネントに接続し、実際に完成したときに `onWin()` を呼びます。共通画面が `onClear(gameId)` を記録し、再クリアで報酬が重複することを防ぎます。
3. ローカルで公開日当日を選び、試遊後にお部屋へ戻ります。神経衰弱でツリーのライト、スライドでリース、ジグソーでツリーの下のプレゼントが増えます。リロードして残ることも確認してください。
4. 正式提供を決めたゲームだけ `status` を `development` から `ready` に変更します。日本時間の公開日と提供状態の両方を満たすと通常画面に「あそぶ」が現れます。この変更は次のビルドに反映されます。

## 検証と公開準備

- `npm.cmd test` で日本時間の境界、25件のデータ・参照画像とスライド盤面を検査します。
- `npm.cmd run build` で本番ビルドと型チェックを実行します。その後 `npm.cmd start` でローカル本番版を開けます（既定はポート3000）。本番では `/dev/preview` は404になります。
- 開発サーバーを起動した状態で `node --experimental-strip-types tests/browser.mjs` を実行すると、EdgeとPlaywrightでPC・Android相当・iPhone相当の画面を操作します。テスト用ブラウザプロファイルに記録するため、自分の試遊記録と区別できます。
- ビルド後の `node tests/production.mjs` は、独立したローカルテストプロセスの時計を進め、JST午前0時の自動更新、未来コンテンツ、開発URL・画像の制限、ゲーム3作品の公開日、翌年の表示を検査します。
- 将来Vercelで公開するときはこのフォルダーをRoot Directory、Framework PresetをNext.jsに設定します。この構成ではサーバー時刻を使います。ソースを公開リポジトリに掲載すると未公開素材もソースから読めるので、先行登録する場合は非公開リポジトリが適しています。

ジグソーには「雪降るクリスマスマーケットの猫たち」を登録済みです。物語・小話・クイズ・日別イラスト・ほかのゲーム画像・25日のクリスマス会は差し替え待ちです。正式素材への切り替えと実機での最終確認は次の段階です。

### 第1段階の確認結果（2026年11月22日）

Windows上のEdgeで、PC（1440×940）、Pixel 7相当（412×839）、iPhone 13相当（390×664）の3サイズを確認しました。各サイズで25日のプレゼント、クイズの両方の回答結果、壁紙ダウンロード、3ゲームの実クリア、装飾の再読み込み、記録リセットが通りました。スマホ相当ではタッチ入力でジグソーの回転・ドラッグも確認しました。Android端末・iPhone実機とSafariでの確認は今後の作業です。

全25日の扉の表示と参照画像、長文表示、開発画面の日付変更を確認しました。本番ビルドでは、未公開扉の本文を取得できないこと、プレビューURLと未公開画像が404になること、ページを開いたまま日本時間12月1日午前0時に最初の扉が開くこと、3ゲームの公開日当日と翌年の表示を検証済みです。
